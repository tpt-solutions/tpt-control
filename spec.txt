tpt-control Design Specification (spec.txt)
1. Overview
Name: tpt-control
Description: A pure-Rust, AI-native control systems theory library. It provides state-space modeling, classical control, optimal control, state estimation, and Model Predictive Control (MPC) with zero C/C++ FFI and zero external solver dependencies.
License: MIT (or MIT/Apache-2.0 dual, but all dependencies must be MIT or compatible).
Core Philosophy: Unit-safe, no_std + alloc compatible at the core, differentiable for reinforcement learning, and mathematically rigorous via native Rust verification tooling and from-scratch implementations.
2. Design Principles
Zero External Solver Dependencies: No LAPACK, no OSQP, no external QP/LMI solvers. All numerical algorithms (Riccati solvers, QP for MPC, matrix exponentials) are implemented from scratch in pure Rust, leveraging tpt-math.
Strict Licensing: No Apache-2.0-only dependencies. The workspace will strictly use MIT, MIT/Apache-2.0 dual, or custom in-house crates to ensure maximum permissive compatibility.
Type-State & Dimensional Safety: Compile-time prevention of dimensional mismatches (e.g., multiplying a 3x1 state vector by a 2x2 gain matrix is a compile error) using Rust's type system and const generics.
Native Formal Verification: Safety and stability invariants are enforced via:
Kani Rust Verifier: For bounded model checking of critical numerical loops (e.g., proving a Riccati iteration converges or doesn't panic on specific matrix conditions).
Property-Based Testing (proptest): For statistical verification of control invariants (e.g., "a stable LTI system subjected to bounded input yields bounded output").
Mathematical Contracts: Documented and tested Lyapunov conditions, enforced via runtime assertions in debug builds and Kani proofs in CI.

4. Crate Specifications
tpt-ctrl-core
Purpose: The foundational layer. Defines continuous and discrete LTI/LTV state-space models (ẋ = Ax + Bu, y = Cx + Du).
Dependencies: tpt-math (internal, MIT).
Key Features:
Const-generic dimensioned matrices (e.g., StateSpace<N, M, P> for N states, M inputs, P outputs).
Exact Zero-Order Hold (ZOH) and Tustin (bilinear) discretization implemented from scratch (e.g., via Padé approximants or scaling-and-squaring for matrix exponentials).
no_std + alloc compatible.
tpt-ctrl-classic
Purpose: Classical frequency-domain and SISO control tools.
Key Features: PID controller with anti-windup (back-calculation), lead-lag compensators, and numerical computation of Bode/Nyquist plots and gain/phase margins using native Rust FFT (from tpt-dsp).
tpt-ctrl-optimal
Purpose: Infinite-horizon optimal control.
Key Features:
From-scratch solvers for Continuous/Discrete Algebraic Riccati Equations (CARE/DARE).
Implementation via structure-preserving Schur decomposition or Newton-Kleinman iteration, avoiding any external LAPACK bindings.
LQR gain computation and LQG (LQR + Kalman) separation principle.
tpt-ctrl-estimation
Purpose: Stochastic state estimation for noisy sensor data.
Key Features: Discrete KF, EKF (with user-provided Jacobian closures), and UKF (Unscented Kalman Filter) for highly nonlinear observation models. Directly consumes filtered sensor streams from tpt-dsp.
tpt-ctrl-mpc
Purpose: Constrained, receding-horizon optimal control.
Key Features:
Linear MPC formulation with explicit constraint matrix generation (state and input bounds).
From-scratch QP Solver: A lightweight, embedded-friendly active-set or interior-point Quadratic Programming solver written in pure Rust, specifically tailored for the structured, banded matrices generated by MPC horizon unrolling. No OSQP or other Apache-only external solvers.
Explicit MPC (mpc-MP) lookup table generation for ultra-low-latency deployment.
tpt-ctrl-verify
Purpose: Mathematical verification of control system safety and numerical robustness.
Key Features:
proptest strategies for generating valid, stable LTI systems and bounded noise profiles.
Kani Rust Verifier harnesses to prove absence of panics (e.g., division by zero, out-of-bounds) in critical solver loops.
Helper traits for defining and checking Lyapunov stability conditions (

6. Phased Rollout (todo.md Alignment)
Phase 0: Foundation & Verification Setup (Weeks 1-2)
Scaffold workspace with strict cargo-deny or similar linting to block Apache-only dependencies.
Implement tpt-ctrl-core (LTI/LTV models, const-generic dimension checks, ZOH discretization).
Set up Kani and proptest harnesses in tpt-ctrl-verify for basic matrix operations.
Phase 1: Classical & Optimal Control (Weeks 3-5)
Implement tpt-ctrl-classic (PID with anti-windup, transfer function algebra).
Build from-scratch CARE/DARE solvers in tpt-ctrl-optimal (Newton-Kleinman or Schur method).
Integration test: LQR on an inverted pendulum model, verified via proptest for stability.
Phase 2: Estimation & MPC (Weeks 6-8)
Build KF and EKF in tpt-ctrl-estimation.
Develop the from-scratch, lightweight QP solver for tpt-ctrl-mpc.
Implement Linear MPC with constraint handling and verify horizon unrolling correctness via Kani.
